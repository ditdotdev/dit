# Dit Documentation

Source-of-truth Markdown for the dit documentation site published at
[dit.dev/docs](https://dit.dev/docs).

## Layout

```
docs/src/
├── index.md             Home (Documentation root)
├── start.md             Getting Started
├── lifecycle/           Installing, configuring, upgrading dit
├── local/               Working with local Docker repositories
├── remote/              Push/pull, clone, remote providers
└── cli/
    ├── cli.md           CLI reference landing page
    └── cmd/*.md         Per-command reference (Cobra-generated)
```

Every `.md` page starts with YAML frontmatter (`title`, `nav_label`,
`nav_order`); the docs-rendering layer in `dit-remote-server` uses
this to build the sidebar nav.

## Editing the CLI reference

Files under `cli/cmd/` are **generated** from the Cobra command tree —
do not edit by hand. They are regenerated by:

```bash
make gen-docs
```

CI runs the same target and fails the PR if the committed reference
differs from what `gen-docs` would produce. Any CLI flag, short-help,
or subcommand change must ship with regenerated `cli/cmd/*.md`.

## Editing the narrative docs

Everything outside `cli/cmd/` is hand-written Markdown. Edit the `.md`
files in place. To preview locally, see the renderer in
[dit-remote-server/services/web](https://github.com/ditdotdev/dit-remote-server/tree/master/services/web):

```bash
cd ../../dit-remote-server/services/web
npm run dev
```

…then visit `http://localhost:3000/docs`.

## Publishing

The docs are published in two places:

* **dit.dev/docs** — the `/docs` route inside the `dit-remote-server` web
  app, which vendors a copy of this `docs/src/` tree under
  `services/web/content/docs/` (`bash docs/sync-to-web.sh`). Updates land
  when the web service redeploys.
* **ditdotdev.github.io/docs** — the Jekyll community site renders a copy
  under its `docs/` directory. `.github/workflows/docs-publish.yml` pushes
  it there on every release (chained from `release.yml`), using
  `bash docs/sync-to-website.sh`. Run that script by hand to preview or
  re-seed the site; `--check` reports drift without changing anything.

Jekyll picks up the same `title` / `nav_label` / `nav_order` frontmatter for
its sidebar. Pages without `nav_order` sort after the numbered ones.
